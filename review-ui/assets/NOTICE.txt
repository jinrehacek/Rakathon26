Files and derivation

pirads_v2.1.png is the unchanged original public template downloaded from:
https://raw.githubusercontent.com/ctsit/imagemap/0bf201d6cb95c7eaedb5449b36e4fa1d9cd9907f/img/pirads_v2.1.png

sectors.json is derived from every actual shape="poly" area in:
https://raw.githubusercontent.com/ctsit/imagemap/0bf201d6cb95c7eaedb5449b36e4fa1d9cd9907f/maps/pirads_v2.1.html
The JSON array is sorted by numeric data-key (1 through 41).
Each points array preserves the source coordinate order and integer values
exactly, including the original polygon for key 41, external urethral sphincter.
Labels preserve upstream titles verbatim, including upstream spelling errors.
No rectangles, synthetic geometry, severity colors or clinical interpretations
were substituted.

The code and column fields come from Other/redcap/sector_crosswalk.csv,
joined by ctsit_key; the label equals both the source title and ctsit_title.
Each column is sur_prostate_regions___ followed by its authoritative code.
Patient right/left are the crosswalk's rs/ls, not inferred from screen position.
The coronal and sagittal drawings on the left have no separate hit areas.
The UI renders these polygons directly as scalable monochrome vector outlines,
grouped into axial levels, seminal vesicles and external urethral sphincter.
The UI displays that last group as "Urethra (atlas)" and explicitly retains the
mapped source title "External urethral sphincter" as a naming discrepancy.
Display lettering is transcribed from the PNG: AFS, PZa, PZpl, PZpm, TZa, TZp,
CZ. It is not derived by uppercasing REDCap codes. Expanded display names use
the zone meanings in the REDCap crosswalk, correcting upstream spelling errors
without modifying the verbatim source titles in sectors.json.
The raster template is retained as a reference asset, but is not stretched behind
the interactive map. Text labels and selection styling are UI annotations.
The 41 polygon definitions and REDCap code associations are unchanged.
The optional full-atlas context view includes the front/side drawings and overlays
the same polygons read-only; editable sector controls remain in the vector panels.
No hit areas, sector projections or lesion contours are invented for front/side
anatomy.

Coordinate frame and checks

The downloaded PNG's IHDR is 513 x 631 pixels, matching the REDCap frame
documented in Other/redcap/REDCAP.md. Points are original-image pixel
coordinates with origin at the top left. No resizing or coordinate transform
was needed. A consuming UI must scale the image and polygons together.
The polygons are selection geometry, not evidence of any patient's findings.

All 41 keys, codes, import columns and titles were checked one-to-one.
Every polygon has at least three vertices, nonzero area and in-frame points.
There are 561 vertices across all 41 polygons; key 41 has 10 vertices.
All 40 boxes in Other/redcap/redcap_areas.json were independently matched
to their nearest original polygon by summed absolute bounding-box corner
offsets, agreeing with the supplied crosswalk and its recorded distances.
Key 41 was additionally compared to the REDCap circle's bounding box
(405.1, 585.2, 423.1, 603.2), as documented in gen_redcap_docs.py.
This comparison checks correspondence, not identical REDCap geometry:
the REDCap boxes are slightly simplified relative to the upstream polygons.
The largest summed corner offset is 22.0 px for pzpm_base_ls.
The original urethra polygon spans x=404..422, y=586..602.
Other/reference/sectors.json was absent; these assets were regenerated
directly from the pinned public HTML, not from that missing local file.
